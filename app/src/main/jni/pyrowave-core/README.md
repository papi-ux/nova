# PyroWave

[PyroWave](https://github.com/Themaister/pyrowave) by Hans-Kristian Arntzen, MIT licensed, vendored
as a prebuilt shared library per ABI.

Upstream builds with CMake and this tree builds with ndk-build, so building it in place would mean
converting the whole native build for one module. The libraries here were produced with the NDK this
app already pins:

```bash
git clone --recurse-submodules https://github.com/Themaister/pyrowave
cd pyrowave && git checkout 186f0393b77f7755953b5ecde994bb1cec2e4155
bash checkout_granite.sh
NDK=$ANDROID_HOME/ndk/27.0.12077973
for abi in arm64-v8a x86_64 armeabi-v7a; do
  cmake -S . -B build-$abi -G Ninja \
    -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake \
    -DANDROID_ABI=$abi -DANDROID_PLATFORM=android-26 \
    -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=$PWD/build-$abi/output \
    -DCMAKE_SHARED_LINKER_FLAGS="-Wl,-z,max-page-size=16384,-z,common-page-size=16384"
  ninja -C build-$abi install
  $NDK/toolchains/llvm/prebuilt/linux-x86_64/bin/llvm-strip --strip-unneeded \
    build-$abi/output/lib/libpyrowave-shared.so
done
```

The linker flags are not optional. Android 15 brought devices with 16 KB memory pages, and a
library aligned to 4 KB will not load on one, so an APK carrying it cannot be installed at all.
`ndk-build` aligns what it links and these are `PREBUILT_SHARED_LIBRARY`, so nothing in this tree
applies that default for them: it has to be asked for here. v1.4.13-beta.3 shipped without it.

Confirm before committing a rebuild, because every other check passes on a misaligned APK:

```bash
readelf -lW build-$abi/output/lib/libpyrowave-shared.so | awk '$1=="LOAD"{print $NF}'   # want 0x4000
python3 tools/check_native_page_alignment.py app/src/main/jni/pyrowave-core/*/libpyrowave-shared.so
```

`tools/test_native_page_alignment.py` asserts it too, so a 4 KB library fails the build rather than a
tester's install.

Each stripped library is about 1.3 MB, and Nova splits APKs by ABI, so an install carries one.

The library needs only libdl, liblog, libm and libc: it carries its own C++ runtime and finds Vulkan
through dlopen, so it adds no `APP_STL` requirement, needs no `-lvulkan`, and an APK holding it still
installs and runs on a device with no Vulkan at all.

Its C API is not ABI stable before 1.0, so `pyrowave.h` here must be the header these libraries were
built from. `PyroWave.apiVersion()` reads the version out of the library rather than trusting that.

Nor is its bitstream, which is why the revision above is pinned rather than left at master, and why it
has to match Polaris's `third-party/pyrowave` submodule. That agreement is what
`PYROWAVE_PROFILE_TOKEN` carries in the RTSP handshake, so all three move together: this checkout,
that submodule, and the token. Two of them agreeing and the third not is a stream that decodes to
noise, which is the failure the token exists to turn into a refusal.

Every Android decoder push is checked by `pyrowave_packet_guard.h` before the codec reads it.
The pinned format has an eight-byte block or sequence header; normal blocks declare their length
in 32-bit words. The guard rejects short headers, lengths below two words, and lengths beyond the
remaining buffer. This also prevents a duplicate block with zero payload words from taking the
codec's duplicate fast path forever without advancing.

This checks packet boundaries only. It accepts valid duplicate blocks, gaps in block indexes, and
sequence headers, and does not require every block or a complete frame. The pinned upstream
`pyrowave.h` permits a frame to span packets and exposes partial-frame readiness separately; Nova
continues to let the codec decide readiness and semantic validity. The C and C++ sanitizer harness
in `tools/test_pyrowave_packet_guard.py` covers those cases and the committed
`app/src/main/assets/pyrowave/selftest-34x30.pw` bitstream. Run it with the other portable checks:

```sh
python3 -m unittest tools.test_pyrowave_packet_guard tools.test_pyrowave_timing
```

`PyroWaveRateModel` carries the bitrate model upstream publishes at that same revision, in a table
generated by `tools/pyrowave_rate_model.py` that records the commit it came from, and Nova's PyroWave
bitrate advice uses 31 dB for handheld and 35 dB for room-distance viewing. It is not part of the bitstream agreement, but it
describes this codec, so when the pin above moves, move `UPSTREAM_COMMIT` and `HEADER_SHA256` in that
script and regenerate the table from the new checkout.
`PyroWaveRateModelTest` fails until the table names the same commit as the checkout line above.

## Measuring the Android renderer

Native code uses `APP_OPTIM=release` even in debug APKs. Symbols and APK debuggability remain
available. For an unoptimized source debugger build, pass `-PnovaNativeOptimization=debug` to
Gradle. `-PnovaNativeDebugChecks=false` is a separate measurement setting: the default debug
checks deliberately inject FEC loss and must be disabled when measuring delivery performance.
The prebuilt codec is already a Release build and is unaffected by these switches.

GPU/CPU timing is off by default. Enable it on the test device before starting a new stream:

```sh
adb -s DEVICE shell setprop debug.nova.pyrowave_timing 1
adb -s DEVICE logcat -s PyroWave:I
```

Set the property to `0` and start a new stream to disable it. It is read at renderer creation;
changing it during a stream takes effect after reconnecting. No overlay is required.

The `timing` log line contains five-second windows and a final partial window at shutdown.
Each metric is **mean milliseconds / maximum milliseconds / sample count**. `-1/-1/0` means
unavailable, not zero work. CPU counts can differ after a refused frame and at window boundaries.

- `gpu_planes_ms`: start of GPU commands through plane decode (or the test path's plane upload),
  including its barriers.
- `gpu_draw_ms`: the following draw interval through command completion, including barriers and
  any GPU wait for the swapchain image. This is not display scanout or end-to-end latency.
- `cpu_fence_ms`: time in the renderer's existing wait for the previous submitted frame.
- `cpu_prepare_ms`: packet parsing/readiness checks, including the first-frame retry if needed.
- `cpu_record_ms`: CPU time recording plane decode/upload commands.
- `cpu_acquire_ms`, `cpu_submit_ms`, `cpu_present_ms`: time inside the corresponding Vulkan calls.

Timestamp reads occur only after the existing frame fence (or device idle at shutdown), without
`VK_QUERY_RESULT_WAIT_BIT`. Unavailable reads are counted separately. A device without timestamp
support, or whose query pool cannot be created, retains CPU timing and continues streaming.
Timestamps can perturb GPU scheduling; compare enabled and disabled runs with the same scene,
resolution, FPS, host settings and network before drawing performance conclusions.

Portable checks: `python3 -m unittest tools.test_pyrowave_timing tools.test_native_optimization`.
The latter needs initialized native submodules and the pinned NDK under `ANDROID_HOME`.

## SGSR 1 upscaling (experimental, PyroWave SDR)

`shaders/sgsr1.frag` is SGSR 1 (Snapdragon Game Super Resolution 1), Qualcomm's spatial, single pass
filter, BSD-3-Clause, adapted after RubyLight's fused YCbCr Vulkan port. `shaders/LICENSE-SGSR1` has the
provenance and the full notice, and the APK carries the same text as `assets/licenses/NOTICE-SGSR1.txt`.
The shader's own header lists every change Nova made to the upstream conventions.

It is off by default, behind **SGSR 1 upscaling (experimental, PyroWave SDR)**, which only builds with
experimental codecs show. `PyroWaveScalerPolicy` decides at session start. Only an SDR stream in Fit or
Stretch whose output is larger than the frame in both directions asks for it, and only then is the
surface's buffer sized to the output instead of the stream. The renderer checks again against the
swapchain it gets and logs one of three states, which `pyrowave_renderer_scaler_state` also returns:

- `DEFAULT`: nothing was asked, and the frame is drawn as before into the stream-size buffer.
- `SGSR1_ACTIVE`: SGSR 1 draws the frame into the output-size buffer.
- `OUTPUT_BUFFER_BILINEAR`: SGSR 1 was asked for and refused here (`HDR_OR_10BIT`, `NOT_UPSCALING`,
  `ASPECT_MISMATCH` or `PIPELINE_FAILED`), so the present shader stretches the frame over the larger
  buffer with its LINEAR sampler. That is not the default: the upscale moved from the compositor into
  the shader, and the log line gives both sizes.

`adb shell setprop debug.nova.pyrowave_sgsr_fail 1` forces `PIPELINE_FAILED` at the next renderer.

The present shaders and their headers are not regenerated for this. `shaders/sgsr1_frag_spv.h` records
the sha256 of the `sgsr1.frag` it was compiled from, the SPIR-V's own sha256, and the compiler, which is
the one that reproduces the vendored present headers byte for byte: Fedora's `/usr/bin/glslc` from
`glslc-2026.1-1.fc44` (sha256 `85365a1f6e439c17cb9d71045d8306c018782359a466ae65c1806be4f7f0cd87`,
shaderc v2026.1, glslang `301b4ede53d59b68bf55f95bb26412d9233c8187`) with
`spirv-tools-libs-2026.1-1.fc44` (`libSPIRV-Tools-opt.so`
`6508a8464b3e53b8c8a5f2aefbd382bb21c0be104286298bc682539cef6b9403`, `libSPIRV-Tools.so`
`06897d4ed1051d4e95b1045288d54230564440064fd117965d742267e7f4834e`). The NDK's own glslc does not
reproduce the present headers, so do not regenerate with it:

```bash
glslc -O shaders/sgsr1.frag -o /tmp/sgsr1.frag.spv
python3 tools/spv_to_header.py sgsr1 /tmp/sgsr1.frag.spv "<compiler identity>"
```

`PyroWaveSgsrReference` is a CPU model of both shaders. The JVM tests hold the shader text to it, compare
it with an independent model of Qualcomm's shader, and show that a wrong offset, flip, chroma centre,
tap, threshold, divisor or edge column changes the result. `PyroWaveSgsrSelfTest` in the debug build
draws the same pictures on the device's GPU offscreen, reads them back and compares; it runs only from
`PyroWaveProofActivity`.

Its native half refuses a request out of contract before any memory or GPU work
(`pyrowave_readback_guard.h`, checked by `tools/test_pyrowave_readback_guard.py`). It stops at the first
failure among its own steps: binding its target and readback memory, beginning and ending its command
buffer, resetting the fence, submitting and waiting. The plane setup it shares with streaming is
unchanged, so a failed plane or staging bind there is still not caught.
`tools/test_pyrowave_readback_failures.py` fails the two binds, the begin, the end and the fence reset
in turn through a fake Vulkan loader. It needs Vulkan headers (`VULKAN_HEADERS_DIR`), skips without
them, and is not in the CI list, so it is run by hand.
